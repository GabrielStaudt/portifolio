# Contribuindo

1. Crie uma branch a partir de `main` com um nome descritivo.
2. Altere os arquivos em `src/`. Não edite `dist/` diretamente.
3. Execute `npm run build` e `npm run check`.
4. Confira as três páginas no navegador em tamanhos de celular e desktop, a navegação por teclado e a impressão do perfil quando afetadas.
5. Abra um pull request explicando o comportamento final e a validação realizada.

## Commits

Use `tipo: descrição curta`:

- `feat`: conteúdo ou funcionalidade nova.
- `fix`: correção de comportamento.
- `docs`: documentação.
- `style`: formatação sem mudança de comportamento.
- `refactor`: reorganização do código.
- `ci`: automação no GitHub.
- `chore`: manutenção.

Exemplo: `fix: corrige navegação da página de projetos`.

Não reescreva o histórico publicado para padronizar commits antigos. Não adicione segredos, arquivos `.env`, dados privados ou informações biográficas não confirmadas.
